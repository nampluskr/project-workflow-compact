# WORKFLOW — 버전 흐름

새 프로젝트를 시작해서 버전을 끝내고 다음 버전으로 넘어가기까지의 흐름을 다섯 단계로 안내한다. 단계마다 사람과 에이전트가 각각 무엇을 하는지, 어느 문서를 쓰는지를 적는다.

- 문서별 절 구성과 작성 기준: [DOCUMENTS.md](DOCUMENTS.md). 풀어 쓰기, 절 안의 보조 표 같은 공통 작성 기준도 여기를 따른다.
- 문서별 빈 양식: [templates/](templates/)
- 이 흐름을 따라 쓴 예시: [specs/v0.1/](../specs/v0.1/)

**원칙은 하나다. 사람이 정하고 에이전트는 묻는다.** 무엇을 만들지는 사람이 정한다. 에이전트는 지어내지 않고 질문해서 받아 적는다.

hook 같은 강제 장치는 두지 않는다. 에이전트가 지킬 규칙은 AGENTS.md 한 곳에 둔다.

## 1. 신규 시작

프로젝트를 처음 열 때 하는 일이다.

**사람**

프로젝트가 무엇을 왜 하는지, 어떤 원칙을 지키는지, 무엇을 다루지 않는지를 정한다. 에이전트의 질문에 답한다.

**에이전트**

사람에게 질문해서 답을 받아 적는다. 답에 없는 내용은 보태지 않는다. 그리고 아래 파일과 폴더를 만든다.

- 루트 `INTENT.md` — [templates/PROJECT-INTENT.md](templates/PROJECT-INTENT.md)를 쓴다.
- 루트 `AGENTS.md` — 규칙 셋을 적는다.
  - 사람이 정하고 묻는다. 문서의 요구·결정은 사람이 정한다. 모르면 지어내지 말고 묻는다.
  - 지난 버전 폴더는 불변이다. specs/ 아래 지난 버전 폴더는 읽기만 하고 고치지 않는다.
  - PROGRESS에 기록한다. 작업을 끝낼 때마다 PROGRESS에 무엇을·결과·검증을 남기고, 계획 밖 작업은 사용자 요청 작업으로 적는다.
- 루트 `CLAUDE.md` — 내용은 `@AGENTS.md` 한 줄이다.
- `specs/v0.1/` — 첫 버전 폴더다.

**쓰는 문서**

루트 INTENT. 절 구성은 [DOCUMENTS.md 3절](DOCUMENTS.md#3-루트-intent)에 있다.

## 2. 작성

버전의 문서를 일을 시작하기 전에 쓴다.

**사람**

버전의 목적과 범위, 설계 결정, 요구를 정한다. 에이전트가 쓴 초안을 읽고 확인하거나 고치게 한다.

**에이전트**

사람에게 묻고, 답을 받아 초안을 쓴다. 아래 순서로 쓴다.

1. 버전 INTENT
2. DECISIONS
3. SPEC
4. PLAN

**쓰는 문서**

`specs/{version}/`에 버전 INTENT, DECISIONS, SPEC, PLAN을 쓴다. 절 구성은 [DOCUMENTS.md](DOCUMENTS.md)의 4~7절에, 빈 양식은 [templates/](templates/)에 있다.

## 3. 진행

PLAN대로 일을 한다.

**사람**

계획 밖에서 요청할 일이 있으면 요청한다.

**에이전트**

PLAN의 Phase 순서로 작업한다. 작업을 끝낼 때마다 PROGRESS에 무엇을·결과·검증을 남긴다. 사람이 계획 밖 작업을 요청하면 PROGRESS의 사용자 요청 작업으로 적는다.

**쓰는 문서**

`specs/{version}/PROGRESS.md`. 절 구성은 [DOCUMENTS.md 8절](DOCUMENTS.md#8-progress)에, 빈 양식은 [templates/PROGRESS.md](templates/PROGRESS.md)에 있다.

## 4. 버전 종료

버전을 끝낸다.

**사람**

버전을 끝낼지 판단한다.

**에이전트**

사람의 판단과 남은 것을 PROGRESS의 "버전 종료"에 기록한다.

**쓰는 문서**

`specs/{version}/PROGRESS.md`의 "버전 종료" 절.

태그·배포 같은 절차는 이 가이드가 정하지 않는다.

## 5. 다음 버전

새 버전을 시작한다.

**사람**

버전 번호를 정한다. 에이전트가 지난 버전의 기록을 정리해 보여 주면 읽고, 새 버전에서 무엇을 할지 정한다.

**에이전트**

`specs/{새 버전}/` 새 폴더를 만든다. 지난 버전 폴더는 그대로 두고 읽기만 한다. 지난 PROGRESS의 남은 것과 사용자 요청 작업을 새 버전 INTENT의 재료로 본다. 이후는 2. 작성부터 같다.

**쓰는 문서**

새 폴더의 버전 INTENT, DECISIONS, SPEC, PLAN, PROGRESS. 지난 버전 폴더의 문서는 읽기만 한다.
